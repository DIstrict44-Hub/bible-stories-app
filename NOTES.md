# Bible Stories — MVP notes

Mobile-first short-form Bible story feed (TikTok/Reels style). Dark cinematic theme: stone arches, firelight, parchment cards.
Built 2026-11-23.

## Stack
- `server.js`: Node 24 + Express 4. Serves the static PWA from `public/` and a small JSON API. Persistence goes to `data/db.json` (likes, comments, saves, entitlements, payments, demo sessions).
- `public/`: vanilla HTML/CSS/JS with no build step (`index.html`, `styles.css`, `app.js`, `demo-checkout.html`, `manifest.webmanifest`, `sw.js`, `icons/`).
- Videos: `public/videos/*.mp4` (720x1280, 18 s, H.264/AAC, faststart) and posters in `public/posters/`. They are generated by `npm run videos`, which runs `scripts/make_bg.py`, a PIL stone-arch and torchlight background, then `scripts/make_videos.py`, an ffmpeg pass that adds a slow Ken Burns zoom, a firelight flicker, Cinzel/Cormorant text cards and a soft drone. Story text and the KJV verses are in `scripts/stories.json`. Feed metadata is in `data/videos.json`.

## Run
- `./start.sh` starts or restarts the server in the background on :8787. The PID goes to `logs/server.pid` and output to `logs/server.log`. If `.env` exists, the script loads it.
- Health check: `curl localhost:8787/api/health`
- Screenshots: `node scripts/screenshot.js [baseUrl]` writes to `screenshots-preview/`. The remove-ads end-to-end check is `node scripts/e2e-removeads.js`. Both need puppeteer-core (`npm i --no-save puppeteer-core@23`) and use /usr/bin/google-chrome.

## Features
- Snap-scroll feed. The visible video autoplays muted, and tapping it (or the pill) unmutes. Off-screen and background videos are paused. The next video is preloaded. Double-tap likes.
- Right rail: like with a count, comments in a bottom sheet with a list and a post form, save, and share (Web Share API, falling back to clipboard and then a prompt). A Saved tab shows a grid of saved stories.
- Ads are placeholders only. There is an interstitial `.ad-slide` every `AD_EVERY` stories (default 4), built by `adSlide()` in `app.js`, and a 320x50 banner `#bannerAd`. Swap both for a real network later.
- PWA: manifest, service worker for the shell only (videos and the API always go to the network), and an "Install now" bottom CTA. The CTA uses `beforeinstallprompt` where the browser supports it and shows an iOS Add to Home Screen sheet as the fallback. Dismissing it hides it for 3 days.
- Payments are one-time only, with no subscriptions anywhere. Stripe Checkout runs with `mode: 'payment'`.
  - Remove Ads: `POST /api/checkout/remove-ads {uid}`. Uses `STRIPE_PRICE_REMOVE_ADS` if set, otherwise `REMOVE_ADS_AMOUNT_CENTS` (default 499).
  - Donate: `POST /api/checkout/donate {uid, amountCents}`. Presets are $3/$5/$10, or a custom amount from $1 to $1000.
  - After the redirect, `GET /api/checkout/verify?session_id=` retrieves the Checkout Session server-side and grants `adFree` when it is paid.
  - Webhook: `POST /api/stripe/webhook` handles `checkout.session.completed` and verifies the signature with `STRIPE_WEBHOOK_SECRET`.
  - The entitlement is stored server-side, keyed by an anonymous uid that is kept in localStorage as `bs_uid`, and mirrored to localStorage as `bs_adfree`.
  - Demo mode applies when there is no `STRIPE_SECRET_KEY`. It shows a "DEMO PAYMENTS" badge and uses `/demo-checkout.html` to simulate paying.

## Env vars (see .env.example)
STRIPE_SECRET_KEY, STRIPE_PRICE_REMOVE_ADS (optional), REMOVE_ADS_AMOUNT_CENTS, STRIPE_WEBHOOK_SECRET, PUBLIC_BASE_URL (optional), PORT, AD_EVERY, CURRENCY.

## Public preview / tunnel status
cloudflared quick tunnels do not work from this box. Outbound QUIC and TCP to port 7844 are blocked, so the edge connection fails and the trycloudflare URL returns a 1033 error. SSH tunnels (localhost.run on :22, pinggy on :443) and tunnelmole (port 8083) are refused by the egress proxy too. Only normal HTTPS egress is allowed. The binary is at ~/bin/cloudflared.
To get a phone URL, either deploy somewhere (Render, Fly, Railway, a VPS, or Vercel with the API split out), or run a tunnel from a machine with open egress.
